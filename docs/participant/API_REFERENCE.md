# API reference

kit 0.5.0 | API `apctt-api-v0.2-draft`

The server exposes seven routes. There is no cancel, batch, upload, callback, WebSocket or scoring
endpoint, and no training endpoint. The frozen OpenAPI description is `contracts/openapi.json`
(served at `/openapi.json`).

| Method and path | Purpose | Success |
|---|---|---|
| `GET /health/live` | Is the process answering? | 200 |
| `GET /health/ready` | Can a new case be accepted right now? | 200 or 503 |
| `GET /v1/package` | Versions, hashes and compute settings of this server | 200 |
| `POST /v1/assessments` | Submit one case | 202 + `Location` |
| `GET /v1/assessments/{assessment_id}` | Read one job (status, result, diagnostics) | 200 |
| `GET /openapi.json` | OpenAPI document | 200 |
| `GET /docs` | Swagger UI (offline, served from `/static/swagger-ui/`) | 200 |

## 1. Conventions

- **Base URL**: `http://127.0.0.1:8000` with `config/dev.json`. The dev profile only listens on a
  loopback address; the server is not meant to be exposed to a network.
- **JSON only**: every API response is `application/json`, except `/docs` and its static files.
- **Authentication**: none by default. If the configuration sets `auth.bearer_token_file`,
  `/health/ready`, `/v1/package` and all `/v1/assessments` routes require
  `Authorization: Bearer <token>` (401 `AUTH_REQUIRED` without it, 403 `FORBIDDEN` if wrong).
  `/health/live`, `/openapi.json` and `/docs` stay open.
- **IDs**: `assessment_id` is 32 lowercase hex characters generated by the server. `trace_id` is a
  new value for every HTTP request; report it when asking the organizer about an error.
- **Times**: UTC, ISO 8601 with milliseconds and `Z`, e.g. `2026-09-29T15:48:23.621Z`.
- **Client input is never echoed**: error responses contain field paths, rule IDs and fixed texts
  only. Query strings and headers such as `?debug=true` or `X-Debug` have no effect.

## 2. `GET /health/live`

```json
{"live": true, "api_version": "apctt-api-v0.2-draft"}
```

Only says that the process answers HTTP. It says nothing about readiness.

## 3. `GET /health/ready`

200 when a new case would be accepted now, otherwise 503 with the same body shape:

```json
{
  "ready": true,
  "reason_code": "READY",
  "loading_policy": "cold_per_case",
  "active_assessment_id": null,
  "compute_status": {"device": "cpu", "require_cuda": false, "status": "NOT_REQUIRED"}
}
```

| `reason_code` | HTTP | Meaning |
|---|---|---|
| `READY` | 200 | A new case will be accepted. |
| `BUSY` | 503 | A case is running; `active_assessment_id` names it. Existing jobs can still be read. |
| `CONFIG_INVALID` | 503 | The package hash differs from `declared_package_sha256`. |
| `STORAGE_CAPACITY` | 503 | `max_jobs` reached or free disk below `min_free_disk_bytes`. |
| `CUDA_UNAVAILABLE` | 503 | A CUDA configuration whose start-up probe found no usable CUDA. |
| `CUDA_RUNTIME_ERROR` | 503 | A CUDA configuration whose probe kernel failed. |
| `RECOVERY_PENDING` | 503 | Processes of an earlier run could not yet be confirmed stopped; retried every 2 s. |

`compute_status` is the start-up compute check: `NOT_REQUIRED` for CPU configurations; for CUDA
configurations it holds the probe result (see [TROUBLESHOOTING.md](TROUBLESHOOTING.md) §8).

## 4. `GET /v1/package`

Identity of what this server runs. Use it to confirm that your configuration and package are the
ones you expect.

| Field | Meaning |
|---|---|
| `package_id` | `module.package_id` from the configuration. |
| `profile` | `dev` or `evaluation`. |
| `api_version`, `schema_version`, `checklist_version` | Versions a request must match (`schema_version`, `checklist_version`). |
| `kit_version`, `contract_version`, `worker_protocol_version` | Versions of this kit, its contracts and the worker protocol. |
| `declared_package_sha256` | The value you declared in the configuration, or `null`. |
| `verified_package_sha256` | The hash the server computed over your package files, or `null` if it could not. |
| `verification_status` | `verified` (computed; matches the declaration if any), `not_verified` (could not compute, e.g. a symlink in the package) or `mismatch` (declared ≠ computed; the server then refuses new cases). |
| `example_only` | `module.example_only` from the configuration. |
| `loading_policy` | Always `cold_per_case`. |
| `config_sha256`, `checklist_sha256` | Hashes of the execution settings and of the checklist file. |
| `compute` | `device`, `require_cuda`, `allow_cpu_fallback`, `precision`, `loading_policy`, `seed`, `visible_devices` and the start-up `probe`. |

Absolute paths, environment variables and secrets are never included.

## 5. `POST /v1/assessments`

Submit one case. Body: `{"request_id": "...", "case": {...}}` ([DATA_CONTRACT.md](DATA_CONTRACT.md) §1).

**Request headers**

| Header | Rule |
|---|---|
| `Content-Type` | `application/json`, optionally with `charset=utf-8`. Anything else → 415. |
| `Content-Encoding` | Absent or `identity`. Compressed bodies → 415. |
| `Content-Length` | Optional. Larger than `max_request_bytes` → 413 before reading. Without it, the limit is applied while reading. |

**Processing order.** Authentication → media type → size → strict JSON → schema and case rules →
`request_id` lookup → readiness and capacity → durable storage → 202. Only after the job is
committed to the store does the server answer 202.

**Responses**

| HTTP | When | Body |
|---|---|---|
| 202 | New job created, or the same `request_id` with the same effective input already exists | Job envelope (§6); header `Location: /v1/assessments/<assessment_id>` |
| 400 | Body is not strict JSON | Error envelope, `INVALID_JSON`, `diagnostics.parse_error` |
| 401 / 403 | Bearer token required / not accepted | Error envelope |
| 409 | `request_id` already used with a different case, configuration or package | `REQUEST_ID_CONFLICT` |
| 413 | Body larger than `max_request_bytes` | `REQUEST_TOO_LARGE` |
| 415 | Wrong `Content-Type` or `Content-Encoding` | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | Schema, version or case rule broken | `REQUEST_VALIDATION_ERROR`, `VERSION_MISMATCH` or `UNSUPPORTED_INPUT_PROFILE` with `field_errors` |
| 503 | Another case is running | `BUSY`, header `Retry-After: 1`; nothing stored — send the same request again later |
| 503 | Server not ready (see `/health/ready`) | `NOT_READY`, header `Retry-After: 1` |
| 503 | Job store full | `STORAGE_CAPACITY` |

A new job is returned as `queued`. A duplicate is returned in its current state, which may already
be `finished` with its result. The case runs in the background: disconnecting does not cancel it,
and there is no cancel endpoint.

## 6. `GET /v1/assessments/{assessment_id}`

Returns the job envelope. HTTP 200 means the lookup worked; the assessment outcome is inside.
Unknown or malformed IDs return 404 `JOB_NOT_FOUND`. Reading never starts a new run.

### 6.1 Job envelope

| Field | Meaning |
|---|---|
| `assessment_id` | Server-generated job ID. |
| `request_id` | Your idempotency key. |
| `job_status` | `queued` (stored, worker not yet started) → `running` → `finished`. |
| `result_origin` | `null` until finished; then `module` (your valid result) or `supervisor` (a failure result built by the server). |
| `result` | `null` until finished; then the result object ([DATA_CONTRACT.md](DATA_CONTRACT.md) §2). |
| `meta` | Identity and timestamps (§6.2). |
| `diagnostics` | Phase, timings and run details (§6.3). |

`job_status` never contains the assessment outcome; `completed`, `abstained` and `failed` are
values of `result.assessment_status`.

### 6.2 `meta`

| Field | Meaning |
|---|---|
| `trace_id` | ID of this HTTP request. |
| `api_version`, `schema_version`, `package_id` | Versions and package in force for this job. |
| `input_sha256`, `config_sha256`, `verified_package_sha256` | Hashes of the case, the execution settings and the package ([DATA_CONTRACT.md](DATA_CONTRACT.md) §5). |
| `accepted_at` | When the job was stored. |
| `started_at` | When the worker process was started (`null` before). |
| `finished_at` | When the final state was stored (`null` before). |

### 6.3 `diagnostics`

While `queued` or `running`:

| Field | Meaning |
|---|---|
| `profile` | `dev` or `evaluation`. |
| `phase` | Same as `job_status`. |
| `worker_phase` | While running: `initializing`, `loading`, `assessing`, `cleaning` or `finished`, as last reported by the worker. |
| `accepted_trace_id` | `trace_id` of the request that created the job. |
| `loading_policy` | `cold_per_case`. |

When `finished`:

| Field | Meaning |
|---|---|
| `phase` | `finished` (`recovered` for jobs closed after a server restart). |
| `timings_ms.load`, `.assess`, `.cleanup` | Milliseconds measured inside the worker around `load`, `assess` and `reset_case`+`close` (GPU work is synchronized before reading the clock). `null` if the step was not reached. |
| `timings_ms.total` | Milliseconds measured by the server from before the worker started until its process group was confirmed gone. |
| `timing_sources` | Which clock produced each timing: `worker_observed` or `supervisor`. |
| `unavailable_reasons` | Why a value is missing, e.g. `{"cleanup": "NOT_REACHED"}` ([TROUBLESHOOTING.md](TROUBLESHOOTING.md) §5). |
| `warning_codes` | Non-fatal events of the run ([TROUBLESHOOTING.md](TROUBLESHOOTING.md) §4). |
| `output_issues`, `output_issues_total` | Only for `INVALID_OUTPUT`: up to 20 `{path, rule}` entries and the total count. |
| `worker_phase` | Last phase the worker reported. |
| `exit_code`, `exit_signal` | How the worker process ended (`exit_signal` set when killed by a signal). |
| `timed_out` | `true` when the time limit was reached. |
| `failure` | Only when the server recorded the failure (`result_origin: supervisor`): `{"code", "message"}`, plus `limit_ms` for `TIMEOUT`. The message is a fixed sentence, e.g. "The model could not process the documents within the 180-second limit." |
| `cleanup_confirmed` | `true` when all processes of the run were confirmed stopped. |
| `raw_output_bytes`, `raw_output_sha256` | Size and SHA-256 of the result bytes your module wrote (`null` if none). |
| `stdout_bytes`, `stderr_bytes`, `stdout_truncated`, `stderr_truncated` | Size of your module's output streams and whether the stored logs were cut at `max_log_bytes`. |
| `compute` | Reported by the worker: `device`, `torch_version`, `torch_cuda_build`, `cuda_available`, `kernel_probe_passed`, `peak_allocated_bytes`, `peak_reserved_bytes`, `measurement_method`. Torch values stay `null` unless your module imported PyTorch; memory values are PyTorch allocator peaks on CUDA only, not whole-device memory. |
| `profile`, `loading_policy`, `accepted_trace_id` | As above. |
| `truncated` | `true` if lists were shortened to respect the 32 KiB diagnostics limit. |

Jobs closed at start-up after an interrupted run carry a shorter block:
`{"phase": "recovered", "previous_status": "queued" | "running", "warning_codes": ["SERVER_RESTARTED"], "failure": {"code": "SERVER_RESTARTED", "message": "…"}}`.
A job closed after an unexpected server error carries
`{"phase": "finished", "warning_codes": ["SUPERVISOR_INTERNAL_ERROR"], "failure": {"code": "INTERNAL_ERROR", "message": "…"}}`.
If that record cannot be written either, the job stays `running` while the server retries the write
(`/health/ready` reports `RECOVERY_PENDING`), then finishes with the same block and
`"phase": "recovered"`.

### 6.4 Polling

Poll every 0.2–1 s until `finished`. A job always reaches `finished`: the worker's time limit
(`limits.deadline_ms`) bounds every run, and a server restart closes interrupted jobs as
`SERVER_RESTARTED`. Only one case runs at a time, so submit the next case after the current one
finishes (or retry on `503 BUSY`).

## 7. Error envelope

Every non-2xx API response has this shape:

```json
{
  "error": {
    "code": "REQUEST_VALIDATION_ERROR",
    "message": "A request field does not satisfy the input contract.",
    "stage": "request_validation",
    "retryable": false,
    "action": "Correct the reported field and submit the request again.",
    "field_errors": [
      {"path": "case.documents[0].sha256", "rule": "document_sha256_match",
       "expected": "SHA-256 of the decoded document", "received_type": "string"},
      {"path": "case.<unknown-field>", "rule": "unknown_field",
       "expected": "only fields defined by the contract", "received_type": "integer"}
    ]
  },
  "meta": {"trace_id": "1c62727a2d2f4e318d1a3024c474ab7b", "api_version": "apctt-api-v0.2-draft"},
  "diagnostics": {"profile": "dev", "duration_ms": 0.2, "truncated": false, "field_errors_total": 2}
}
```

| Field | Meaning |
|---|---|
| `error.code` | Fixed code (table below). |
| `error.message`, `error.action` | Fixed texts for that code. |
| `error.stage` | Where processing stopped. |
| `error.retryable` | `true` if sending the same request later can succeed. |
| `error.field_errors[]` | For 422: `path` (field location, unknown names as `<unknown-field>`), `rule` ([DATA_CONTRACT.md](DATA_CONTRACT.md) §4.1), `expected`, `received_type` (`null`, `boolean`, `integer`, `number`, `string`, `array`, `object`, `missing`). At most 20. |
| `diagnostics.duration_ms` | Time spent on the request. |
| `diagnostics.field_errors_total` | Number of field errors before the limit of 20. |
| `diagnostics.parse_error` | For 400: `{"reason", "line", "column"}` ([TROUBLESHOOTING.md](TROUBLESHOOTING.md) §2). |
| `diagnostics.stack_frames` | Only for 500 in the dev profile: file, line and function inside the server's own code. |
| `diagnostics.truncated` | `true` if the response was shortened to stay within 32 KiB. |

| Code | HTTP | Stage | Retryable | message | action |
|---|---|---|---|---|---|
| `INVALID_JSON` | 400 | request_parsing | no | The request body is not valid strict JSON. | Send UTF-8 JSON without duplicate keys, NaN or Infinity. |
| `REQUEST_VALIDATION_ERROR` | 422 | request_validation | no | A request field does not satisfy the input contract. | Correct the reported field and submit the request again. |
| `VERSION_MISMATCH` | 422 | request_validation | no | The case schema or checklist version does not match the server profile. | Use the versions published by GET /v1/package. |
| `UNSUPPORTED_INPUT_PROFILE` | 422 | request_validation | no | The input profile is not supported by this server. | Submit a pdf_report case. |
| `REQUEST_TOO_LARGE` | 413 | request_size | no | The request body exceeds the configured size limit. | Reduce the case size; the server never truncates input. |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | request_headers | no | Only application/json with identity encoding is accepted. | Send Content-Type: application/json without Content-Encoding. |
| `REQUEST_ID_CONFLICT` | 409 | admission | no | The request_id was already used with a different effective input. | Use a new request_id for a different case or configuration. |
| `BUSY` | 503 | admission | yes | An assessment is already running on this server. | Retry later with the same request_id. |
| `NOT_READY` | 503 | admission | yes | The server is not ready to accept assessments. | Check GET /health/ready and retry after the operator resolves the reason. |
| `STORAGE_CAPACITY` | 503 | admission | yes | The job store has reached its configured capacity. | Ask the operator to archive previous runs before submitting new cases. |
| `JOB_NOT_FOUND` | 404 | lookup | no | No accessible assessment has this ID. | Use the Location header returned at submission. |
| `ROUTE_NOT_FOUND` | 404 | routing | no | No API route matches this path. | See GET /openapi.json for the available routes. |
| `METHOD_NOT_ALLOWED` | 405 | routing | no | This method is not allowed for the route. | See GET /openapi.json for the allowed methods. |
| `AUTH_REQUIRED` | 401 | authentication | no | Credentials are required. | Send the bearer token issued by the operator. |
| `FORBIDDEN` | 403 | authentication | no | The credentials are not accepted. | Use the credentials issued by the operator. |
| `INTERNAL_ERROR` | 500 | internal | no | The server hit an unexpected error. | Report the trace_id to the operator. |

## 8. `/openapi.json` and `/docs`

`/openapi.json` returns the OpenAPI 3.1 document; it equals `contracts/openapi.json`. `/docs` serves
Swagger UI 5.33.0 from `/static/swagger-ui/` with no external requests (the online validator is
disabled). `/redoc` is not available.

## 9. Client examples

Submit and poll with `curl`:

```bash
LOCATION=$(curl -s -o /dev/null -D - -X POST http://127.0.0.1:8000/v1/assessments \
  -H 'Content-Type: application/json' --data @docs/EXAMPLE_REQUEST.json \
  | awk -F': ' 'tolower($1)=="location"{print $2}' | tr -d '\r')
curl -s "http://127.0.0.1:8000$LOCATION"
```

Submit and poll with Python's standard library, retrying on `BUSY`:

<!-- example: python-client -->
```python
import json
import time
import urllib.error
import urllib.request

BASE = "http://127.0.0.1:8000"


def call(method, path, body=None):
    """Return (status, headers, JSON body). Header lookups are case-insensitive."""
    data = None if body is None else json.dumps(body).encode("utf-8")
    request = urllib.request.Request(BASE + path, data=data, method=method)
    request.add_header("Content-Type", "application/json")
    try:
        with urllib.request.urlopen(request, timeout=30) as response:
            return response.status, response.headers, json.loads(response.read())
    except urllib.error.HTTPError as error:
        return error.code, error.headers, json.loads(error.read())


def assess(body, timeout_s=600):
    deadline = time.monotonic() + timeout_s
    while True:
        status, headers, envelope = call("POST", "/v1/assessments", body)
        if status == 202:
            break
        if status == 503 and envelope["error"]["retryable"] and time.monotonic() < deadline:
            time.sleep(float(headers.get("Retry-After", "1")))
            continue
        raise RuntimeError(f"{status} {envelope['error']['code']}: {envelope['error']['field_errors']}")
    location = headers["Location"]
    while envelope["job_status"] != "finished":
        if time.monotonic() > deadline:
            raise TimeoutError(location)
        time.sleep(0.5)
        _, _, envelope = call("GET", location)
    return envelope


with open("docs/EXAMPLE_REQUEST.json", encoding="utf-8") as handle:
    job = assess(json.load(handle))
print(job["result_origin"], job["result"]["assessment_status"], job["diagnostics"]["timings_ms"])
```
