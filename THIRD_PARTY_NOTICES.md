## Common base environment: installed by the organizer, not bundled

Decisions D60 and D67 (2026-10-10): every team's module runs in one common base environment, the
CUDA base above plus a curated set of packages, pinned in `requirements-base.lock` (94 packages,
Linux x86_64, CPython 3.12; input `requirements-base.in`, plain pins `constraints-base.txt`). The
kit ships only these lists, names, versions and hashes; the packages are **not bundled** and not
redistributed. The organizer installs the base read-only on its machines from PyPI and the PyTorch
cu128 page; teams install it for development with `tools/make_env.py` and accept each package's
licence there. On 2026-10-10 `tools/check_licenses.py` read the metadata of all 94 Linux wheels:
73 allowed, the 20 CUDA base packages above flagged as organizer-installed (D52), none other
denied, and one for review: pypdfium2 5.14.0 declares "BSD-3-Clause, Apache-2.0, dependency
licenses" (PDFium and the libraries built into it keep their own licences, listed in the wheel).
bitsandbytes 0.50.2 (MIT, `License-Expression: MIT`, licence file "Copyright (c) Facebook, Inc. and
its affiliates"; added for the catalogue's 4-bit LLMs, D67) ships its own compiled CUDA and CPU
libraries and no NVIDIA library: its CUDA 12.8 library uses `libcudart.so.12`, `libcublas.so.12`
and `libcublasLt.so.12` from the NVIDIA packages above.
The per-package versions, import names, sizes and this summary are in
`contracts/base-environment.json`. A screening record, not legal advice.

## Licence checker

`tools/check_licenses.py` and `contracts/license-policy.json` are part of this kit (MIT). They
screen team bundles and web systems against the licence policy from declared metadata and name
rules; see [docs/participant/LICENSING.md](docs/participant/LICENSING.md). They flag components;
they do not grant licences or give legal advice.
